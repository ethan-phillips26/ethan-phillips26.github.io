DMR Hearings

The North Dakota Industrial Commission streams every oil and gas hearing to YouTube, which adds up to hundreds of hours of testimony that nobody can search. This project indexes the captions of every hearing since December 2021 alongside the official dockets, splits each hearing into its individual cases, and links every result to the exact timestamp in the video.

How it's built

A pipeline downloads each hearing's auto-captions with yt-dlp and parses the official docket PDFs with pypdf. Hearings follow a script ("next case is case number…"), so those phrases are used to split each hearing into individual cases. Case numbers the captions mishear are corrected against the docket, and spans that couldn't be placed with confidence are flagged.

Search combines BM25 keyword search and vector search over overlapping 75-second chunks, merged with reciprocal rank fusion. Everything lives in a single SQLite file using FTS5 and sqlite-vec, with embeddings from a small CPU model, so it runs locally with no API keys. Each chunk is embedded with its case number and applicant, which lets a search for a company find testimony that never mentions it by name.

How I use it

The search is exposed through an MCP server with five read-only tools. Claude can search the hearings, read the surrounding transcript, and cite the case number, hearing date and timestamp for each claim. There is also a command-line search for checking results directly. Most hearings end without a ruling, so the tools never report an outcome.
